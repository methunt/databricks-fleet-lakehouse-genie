How it was built

Eight choices, each with a reason

The transformation and tuning decisions behind the pipeline.

1

Yearly batches, not a daily replay

The first plan replayed 1,096 daily files. An hour in, about a third of the days had landed and two earlier runs had already died, so I stopped it. Yearly files give the same streaming behaviour in minutes.

2

Streaming for facts, materialized views for aggregates

A streaming table is append-only. A GROUP BY inside one appends a partial group on each batch instead of recomputing.

3

Liquid clustering

Auto Loader lands files in arrival order. Clustering on each table's filter column keeps date and ID filters from scanning everything.

4

Year in the cluster key

CLUSTER BY and PARTITIONED BY cannot be combined in Lakeflow. Three years is too coarse to partition on anyway.

5

optimizeWrite on silver and gold

It merges the small files that three batches leave behind. Bronze output is already ordered, so it would add cost for nothing.

6

Expectations on silver

Null dates, negative revenue and missing customers are dropped before any join or aggregate sees them.

7

schemaHints and a rescue column

Column types stay fixed across the yearly files, and malformed rows are kept aside instead of failing the load.

8

Metric views read the trip fact

The source's pre-aggregated tables cannot be re-aggregated correctly. See the data-quality findings below.

∑

Ratios from summed values

Every ratio is MEASURE(a) / MEASURE(b) over sums, never an average of averages.

Data quality

What the data got wrong, and how it was caught

Each finding changed how the layers are built.

Finding 1 · {{gap_pct}} revenue gap

The source file disagrees with itself

The dataset ships pre-aggregated driver and truck monthly tables that total {{src_rev}}. The {{trips}} trip rows total {{rev}}, a difference of {{gap_rev}}. Their on-time rate also differs: {{src_otp}} against {{otp}}. The metric views read the trip rows and the monthly tables are not used. Those tables hold {{agg_lo}} to {{agg_hi}} fewer rows than the trip fact, so they look cheaper to scan, but they cannot be trusted.

Finding 2
{{unassigned_trips}}

Trips with no driver

An empty driver_id. They explain the whole trip-count gap ({{trips}} against {{src_trips}}) but only {{unassigned_gap_share}} of the revenue gap ({{unassigned_rev}}). They are labelled Unassigned, not dropped. The remaining {{unexplained}} is unexplained.

Finding 3
{{mpg4}}

An average of averages is not an average

Averaging per-trip MPG gives 6.5015. Summed miles over summed gallons gives {{mpg4}}. On-time rate must divide by the {{logged}} logged deliveries, not all {{trips}} trips.

Finding 4 · {{bad_lost}} revenue lost

Joining two views on the wrong grain halves the revenue

Asked which trucks cost most to maintain relative to what they earn, the Genie agent joined two views on truck and month. Dispatch months and service months rarely match, so the join kept {{bad_rev}} of {{rev}} and reported a top ratio of {{bad_ratio}}. Joined on truck alone it keeps {{good_rev}} ({{good_kept}}) and the ratio is {{good_ratio}}. A rule in the agent's instructions plus an example query fixed it.

Finding 5 · 0 rows

A successful pipeline run produced an empty table

A join compared 'delivery' against data that says 'Delivery', so every row failed to match. The update still reported COMPLETED, and gold.on_time_delivery was empty. A row count caught it, not the run status.

Learnings

What I learned

Read the fact grain

A pre-aggregated table that saves a join can disagree with the facts and cannot be re-aggregated.

Check row counts

After every refresh. COMPLETED does not mean the table has data.

Examples beat instructions

A prose rule to exclude Unassigned was ignored. The same rule as an example query was followed on the retest.

Write down the safe join

Two views that each look correct can lose half the revenue when joined on the wrong key.

Batch what you can

Three yearly files replaced an hour-long replay that was a third done.

Generate summaries from data

This page and the README banners are built from a data file, so a missing figure fails the build instead of shipping a blank.
